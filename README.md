# Hex Map · GitHub Pages

Браузерный редактор H3-карт с русскоязычной векторной подложкой Москвы и Санкт-Петербурга. CSV выбирается на компьютере пользователя и обрабатывается в браузере. Сервер обработки данных, Python, Jupyter и сборка проекта не требуются.

## Опубликовать

1. Создайте пустой репозиторий GitHub с основной веткой `main`.
2. Загрузите **содержимое этой папки** в корень репозитория. Рядом с `index.html` должны оказаться `src`, `vendor`, `assets`, `tiles`, `regions.json` и скрытая папка `.github`. Другие версии проекта и пользовательские CSV переносить не нужно.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Publish GitHub Pages → Run workflow**. Последующие изменения в `main` публикуются автоматически. Если workflow уже запустился после загрузки, дождитесь его завершения.
5. Адрес сайта появится в **Settings → Pages** и в завершившемся workflow: `https://USERNAME.github.io/REPOSITORY/`.

При переносе через GitHub Desktop добавьте эту папку как отдельный репозиторий и опубликуйте его. При переносе через Git команды выполняются **внутри `Hex_web`**:

```sh
git init -b main
git add .
git commit -m "Prepare Hex Map for GitHub Pages"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Репозиторий должен разрешать GitHub Actions и GitHub Pages на вашем тарифе. Конфигурация публикации находится в `.github/workflows/pages.yml`. Все пути относительные: сайт работает и в корне домена, и по адресу `/REPOSITORY/`.

## Создать карту

1. Откройте сайт и выберите город.
2. Выберите CSV, при необходимости измените кодировку и десятичный знак.
3. Проверьте колонки H3, значения и необязательного фильтра. Дополнительные колонки можно включить в подсказки. Нажмите **«Показать данные на карте»**.
4. Настройте группу, шкалу, цвета, подписи, легенду и тексты в правом меню. Масштабируйте и перемещайте карту: пунктирная рамка показывает область экспорта. Заголовок и легенда внутри рамки имеют то же расположение, пропорции и переносы строк, что в PNG, SVG и автономном HTML.
5. Скачайте PNG или SVG соответствующими кнопками, либо автономную карту кнопкой **«Скачать HTML»**. Экспорт использует текущие настройки.

Заголовок, подзаголовок карты и название легенды поддерживают переносы строк: нажмите **Enter** в поле или вставьте **`<br>`** (также подходит `<br/>`). Длинные строки переносятся автоматически по ширине макета. Остальные HTML-теги отображаются как обычный текст. Заголовок расположен поверх карты вверху слева, легенда — внизу слева. Макет HTML сохраняет исходное соотношение сторон при изменении размера окна. Если заголовок и легенда не помещаются, появится сообщение в меню: увеличьте высоту файла, сократите текст или уменьшите шрифт легенды.

Схема CSV — заголовок и до **50 000 строк**, размер файла до 100 МБ:

| Колонка | Содержимое |
| --- | --- |
| `hex_id` | Валидный H3-индекс в шестнадцатеричной записи, как текст |
| `value` | Число; пустая ячейка означает отсутствие данных |
| `group` | Необязательная группа или показатель для фильтра |
| Другие колонки | Необязательные поля для подсказок |

Названия колонок могут отличаться — выберите их в интерфейсе. Поддерживаются UTF-8 и Windows-1251; разделитель CSV определяется автоматически. Для десятичных запятых удобно использовать CSV с разделителем `;` и выбрать **«Запятая»**. Все гексы в одном CSV должны иметь один уровень H3 и находиться внутри выбранной подложки. Ошибочные индексы и повторяющиеся пары «гекс + группа» сопровождаются сообщением с номером строки.

В фильтре **«Все»** гексы, встречающиеся в нескольких группах, получают среднее непустых значений. В отдельных группах показываются исходные значения. Если все значения гекса пустые, он остаётся без данных.

Чтобы обновить карту, выберите новый CSV, проверьте колонки и снова нажмите **«Показать данные на карте»**. Оформление сохраняется до закрытия или перезагрузки страницы. Кнопка **«Скачать настройки JSON»** сохраняет оформление, город, выбранную группу, положение карты и соответствие колонок отдельным файлом на компьютер. При следующем запуске откройте этот JSON и выберите CSV. Данные CSV в JSON не включаются.

## Шкала и цвета

- Непрерывная шкала использует минимум и максимум данных. Симметрия относительно нуля действует только при наличии значений обоих знаков. Ноль выделяется, если есть в данных или находится между отрицательными и положительными значениями.
- Для обоих знаков доступны расходящиеся палитры. Magma, Viridis и последовательная палитра предназначены для данных одного знака. Палитры можно переворачивать и редактировать.
- В дискретном режиме свои границы вводятся по возрастанию через `;`, включая минимум и максимум. Крайние границы должны покрывать данные; для обоих знаков нужна граница `0`. Пустое поле возвращает равные интервалы.
- Точное значение внутренней границы относится к следующему интервалу в сторону больших чисел. Например, при границах `0; 5; 10` значение `5` получает цвет верхнего интервала, `10` входит в последний интервал. Ноль при наличии отдельного цвета остаётся отдельным значением.
- В легенде дискретные цвета идут от меньшего снизу к большему сверху, числа стоят на границах. Дополнительной строки «нулевое значение» нет; цвет нуля на карте сохраняется. Округление меняет только подписи.

Две палитры сразу подставляют готовые интервалы:

| Палитра | Границы | Цвета от меньшего к большему |
| --- | --- | --- |
| Красно-зелёная | `-15; -10; -5; 0; 5; 10; 15` | `#5e150b`, `#c44b0e`, `#f5b87b`, `#b4e8a0`, `#46d742`, `#0f7e19` |
| Последовательная | `3; 4; 5; 6; 7; 8; 9; 10` | `#bc4821`, `#f0754c`, `#ee9b6a`, `#e3bc7e`, `#aec561`, `#73b243`, `#2b6f25` |

Если данные выходят за готовые границы, задайте подходящие границы или очистите поле. Пока границы некорректны, экспорт недоступен.

## Результат

| Формат | Что сохраняется |
| --- | --- |
| PNG | Карта с заголовком, легендой и подписями. По умолчанию 3200 × 2400 px; размер задаётся в интерфейсе. При одинаковом соотношении сторон изменение разрешения не меняет пропорции оформления. |
| SVG | Векторные гексы, легенда и заголовок. Подложка и топонимы — встроенные растровые изображения. |
| HTML | Один файл, открывается двойным кликом без интернета. Встроенная подложка-снимок, интерактивные гексы, подсказки и переключение групп. |

В HTML попадают гексы, пересекающие рамку экспорта. Опция **«Все группы в HTML»** включает переключатель; при выключении сохраняется только выбранная группа. Диапазоны шкал сохраняются по исходным данным, чтобы обрезка области не меняла цвета. Снимок подложки ограничен областью рамки: при приближении новых улиц и подписей не появляется. Размер HTML зависит от площади снимка, размера изображения, числа гексов, групп и дополнительных полей. Полный PMTiles в HTML не встраивается.

На самом сайте подложка остаётся векторной и загружается с GitHub Pages по частям. CSV не отправляется в сеть. Автономный HTML содержит выбранные данные и поля подсказок — передавайте его тем, кому эти данные предназначены.

## Подложки и новые города

`regions.json` — каталог территорий. В `tiles` уже включены Москва и Санкт-Петербург с окрестностями; оба архива имеют максимальную детализацию тайлов **z12**. При большем приближении тайлы увеличиваются, новая детализация не добавляется. Подписи Protomaps настроены с `lang: "ru"`; при отсутствии русского названия применяется fallback стиля.

Для нового города подготовьте совместимый с Protomaps PMTiles-архив с нужным покрытием и детализацией, добавьте его в `tiles` и внесите запись в `regions.json`:

```json
{
  "id": "new-city",
  "name": "Название города",
  "url": "tiles/new-city.pmtiles",
  "bounds": [WEST, SOUTH, EAST, NORTH],
  "center": [LONGITUDE, LATITUDE],
  "zoom": 10,
  "maxzoom": 12,
  "date": "YYYY-MM-DD"
}
```

Числовые заполнители замените числами, дату — датой данных. Координаты везде в порядке **долгота, широта**. `bounds` должны соответствовать покрытию файла. Приложение само не скачивает и не вырезает новые города. Для обновлённого архива удобно использовать новое имя файла и поменять `url`, чтобы браузер не использовал прежний кэш.

Файлы более 100 МиБ нельзя добавлять обычным Git push; при росте подложек вынесите их на хранилище с поддержкой HTTP Range и CORS и укажите абсолютные HTTPS-адреса в каталоге. Для двух включённых городов дополнительное хранилище не нужно.

## Что находится в папке

| Путь | Назначение |
| --- | --- |
| `index.html` | Страница редактора |
| `src/app.js` | Интерфейс и MapLibre-карта |
| `src/data.worker.js` | Чтение CSV и подготовка H3 в отдельном потоке |
| `src/scale.js`, `src/legend.js` | Общая логика шкал и легенды для сайта и экспорта |
| `src/export.js`, `src/viewer.js` | PNG/SVG и автономный HTML |
| `src/style.css` | Оформление интерфейса |
| `vendor` | Закреплённые браузерные библиотеки и их лицензии |
| `assets/fonts`, `assets/sprites` | Шрифты и символы подложки с лицензией шрифтов |
| `tiles`, `regions.json` | Векторные подложки и каталог |
| `.github/workflows/pages.yml` | Публикация GitHub Pages |

Библиотеки: MapLibre GL JS **5.0.1**, PMTiles **4.2.1**, Protomaps Basemaps **5.7.2**, H3 JS **4.3.0**, Papa Parse **5.5.3**. Они уже включены: при открытии сайта скачивание библиотек с CDN не требуется. Лицензии сохранены в `vendor/LICENSE-*.txt`, `assets/fonts/LICENSE.txt` и `tiles/LICENSE.txt`; их нужно сохранять при публикации. Атрибуция OpenStreetMap и Protomaps остаётся на карте и в экспорте.

Для работы нужен современный браузер с WebGL. Сам редактор открывается по HTTP(S); двойной клик предназначен для скачанного автономного HTML.
